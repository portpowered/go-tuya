# Provider evidence

The maintainer reports that the implemented flows worked with real Tuya
accounts. Those tests were not recorded with sanitized exchanges or
route-by-route provenance. Offline tests use synthetic responses; they show
what this client sends and accepts, not Tuya's verified wire contract.

The [generated API reference](https://portpowered.github.io/go-tuya/) and
[OpenAPI source](https://github.com/portpowered/go-tuya/blob/main/api/openapi.yaml)
list the HTTP routes used by the client. Each route is labeled as
provider-documented or implementation-derived. Implementation-derived routes
record current client behavior, not a verified Tuya contract. Related Tuya APIs
may use different paths or response shapes.

Selected route examples:

| Operation | Client route | Evidence scope |
| --- | --- | --- |
| Device list | `GET /v1.0/devices` | Tuya documents this route and selected fields in [Get Device List](https://developer.tuya.com/en/docs/cloud/7ccd629a6c?id=Kconjb15xpvd3). |
| QR login | `/v1.0/m/life/home-assistant/qrcode/tokens` | Implementation-derived. Tuya's [QR login guide](https://developer.tuya.com/en/docs/app-development/userqrlogin?id=Kceugtdh6y3h9) describes SDK calls, not this HTTP contract. |
| Token refresh | `/v1.0/m/token/{refresh_token}` | Implementation-derived. Tuya's [Refresh Token](https://developer.tuya.com/en/docs/cloud/80bb968f1d?id=Ka7kjv3j8jgvr) page documents another route and response. |
| Home list | `/v1.0/m/life/users/homes` | Implementation-derived. [Query Home List](https://developer.tuya.com/en/docs/cloud/f5dd40ed14?id=Kawfjh9hpov1n) documents a different route. |
| Home devices | `/v1.0/m/life/ha/home/devices` | Implementation-derived. [Query Devices in Home](https://developer.tuya.com/en/docs/cloud/d7ee73aadb?id=Kawfjer0wkt2a) documents a different route. |
| Device status | `/v1.0/m/life/devices/{device_id}/status` | Implementation-derived. Tuya documents a different route in [Get Device Status](https://developer.tuya.com/en/docs/cloud/1ef1a3044b?id=Kconf2usgnfwo). |
| Camera RTC | `/v1.0/m/life/ipc/{device_id}/webrtc/session` | Implementation-derived. The [WebRTC guide](https://developer.tuya.com/en/docs/iot/webrtc?id=Kacsd4x2hl0se) describes another flow. |

The device-list reference does not specify the Device Sharing signing and
encryption transport. A documented route match does not verify that transport
or response fields beyond those shown by Tuya. No sanitized live exchanges or
private account/device captures are included in this repository.

The OpenAPI server list follows the library's configured cloud and QR login
hosts. Tuya's [general Cloud API endpoint list](https://developer.tuya.com/en/docs/iot/api-request?id=Ka4a8uuo1j4t4)
uses a different US host, so these server choices are implementation-derived
for this Device Sharing client.

Message queue connections use MQTT topics returned by Tuya's queue
configuration. Their channel and event behavior is documented separately in
the [AsyncAPI inventory](https://github.com/portpowered/go-tuya/blob/main/api/mqtt.asyncapi.yaml)
as implementation-derived. The event parser handles legacy protocol 4 and 20
messages; these details do not establish a complete provider event catalog.
