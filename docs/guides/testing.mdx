# Testing and evidence

Run the local checks from the repository root:

```sh
make lint
make check
make coverage
make replay
```

`make coverage` measures non-generated Go code under `pkg/` and enforces an
80% minimum. Replay tests inject an HTTP transport and read hand-authored
fixtures from `tests/replay/fixtures`. Those fixtures are synthetic examples of
the current implementation; they are not Tuya captures and do not validate
private provider schemas.

All 28 schema HTTP operations have stored synthetic request/response pairs.
Replay checks the method, origin, escaped path, query, relevant headers, and
body before returning the paired response. Encrypted values are decrypted and
compared with fixture meanings; signatures are recomputed. An ordered MQTT
transcript starts with the paired encrypted HTTP configuration request, then
checks MQTT factory options, connect, owner/device subscriptions, incoming events,
callbacks, unsubscribe, and disconnect. Both transports reject unexpected or
duplicate exchanges and require every expected exchange to be consumed. These
synthetic checks do not establish live provider behavior.

The current non-generated statement result is 82.6% (1,308/1,583). The raw
`go tool cover` total includes generated wire code, so it is not the release
metric. Remaining low-coverage areas include MQTT retry and expiry branches
(`runMQTTLoop` 57.7%, `connectMQTT` 69.0%) and unimplemented public placeholders
such as `UserService.Unload` and `GetDeviceStreamAllocate` (0%). The synthetic
lifecycle tests cover initial failure, reconnect error reporting, and orderly
stop; they do not prove broker behavior with a real account.

The maintainer reports that the implemented flows worked with real Tuya
accounts, but the account tests were not recorded with sanitized exchanges or
route-by-route provenance. No private account or device captures are included
in the repository.

An opt-in integration test makes read-only account requests. Use a test account
and keep credentials out of shell history and shared output:

```sh
TUYA_AUTH_TOKEN="$TUYA_AUTH_TOKEN" \
TUYA_REFRESH_TOKEN="$TUYA_REFRESH_TOKEN" \
TUYA_AUTH_TOKEN_EXPIRED="$TUYA_AUTH_TOKEN_EXPIRED" \
go test -tags=integration ./pkg/tuya -run TestIntegration_DeviceManagementWorkflow
```

See [the integration test](https://github.com/portpowered/go-tuya/blob/main/pkg/tuya/integration_test.go)
for setup details. Live tests are excluded from pull-request CI.
